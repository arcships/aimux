## Findings

### F1. §3 Kimi 行「k2: `thinking_budget: 0`」无任何来源，与调研及官方文档矛盾（P1，**blocking**）
- **手册位置**：[provider-config-manual.md](D:\code\aimux\docs\provider-config-manual.md#L56)（§3 Kimi/Moonshot 行：「k2: `thinking_budget: 0`；k2.5/k2.6: `thinking:{type:"disabled"}`；k2.7-code: 不可关」，备注「by-model 三套（batch-04）」）
- **证据**：
  - batch-03.md:965 —— by-model 三套机制只含 `kimi-k3`（reasoning_effort low/high/max）、`kimi-k2.7-code`（thinking.type 仅 enabled）、`kimi-k2.6/k2.5`（thinking.type enabled/disabled + k2.6 的 keep）；**无「kimi-k2」模型、无 `thinking_budget` 字段**；k2.5 的关思考 wire 明确是 `thinking:{type:"disabled"}`
  - batch-04.md:784、1514 —— 只含 k3/k2.6/k2.7-code，总结写「两套」（k3 + k2.6），无 k2、无 thinking_budget
  - _global_table.md:45、56 —— Kimi 相关仅 `thinking:{type,keep}`（k2.6）与「不可关 kimi-k2.7-code」，无 thinking_budget
  - Kimi 官方文档（platform.kimi.com/docs/guide/use-thinking-models，本次 WebFetch 复核）：模型清单为 k3/k2.7-code/k2.6/k2.5，请求字段对照表为 `reasoning_effort` / `thinking.type` / `thinking.keep` 三列，**无任何 `thinking_budget` 参数**；k2.5 关闭思考 = `thinking.type:"disabled"`
- **判定**：若「k2」指 kimi-k2.5，手册给出的关思考 wire（`thinking_budget: 0`）与 batch-03 及官方文档（`thinking:{type:"disabled"}`）矛盾；若「k2」指某个独立模型，则该模型在调研与官方文档中均不存在。无论哪种解释，该子条目为**编造/无来源且错误** → blocking。
- **建议修复**：删除「k2: `thinking_budget: 0`」子句，改为「k2.5/k2.6: `thinking:{type:"disabled"}`；k2.6 另可 `thinking.keep`；k2.7-code 不可关；k3 用 reasoning_effort low/high/max（默认 max）」，并按 batch-03 补充三套来源。

### F2. §3 SiliconFlow 行以 `thinking_budget: 0` 作「关思考」wire，语义无证据（P2，non-blocking）
- **手册位置**：provider-config-manual.md#L60（「`thinking_budget`（思维链上限）｜示例 `{ thinking_budget: 0 }`（或调低）」）
- **证据**：batch-05.md:1091 —— `thinking_budget` 是「思维链 token 上限，Qwen3 系原生强制截断，其他模型可能继续」，无「0 = 关闭思考」语义；_global_table.md:54 把 siliconflow 归入 `enable_thinking` + `thinking_budget` 族（也未给 0 语义）
- **判定**：条目内容（thinking_budget 存在、Qwen3 系原生）与 batch-05 一致，但「0=关」是无证据的外推；手册已用「（或调低）」缓解 → non-blocking，但建议改为「调低预算」表述并标注「0 是否等效关闭未经官方确认」。
